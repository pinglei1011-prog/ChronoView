# ChronoView 0.2.9 视频持续卡顿验证

日期：2026/11/24（北京时间）。在现有项目继续修改，保留 0.2.8 等旧版与原始媒体。

## 原因与改动

用户反馈 F:/photo 其他视频仍然“画面一顿一顿，声音基本正常”。0.2.8 只处理后台封面竞争，未解决视频窗口漏绘。

已审阅随包 Qt 6.10.3 的 qvideowidget.cpp、qvideowindow.cpp、qwindow.cpp 和 Windows 平台更新调度源码。QVideoWindow.setVideoFrame() 使用 requestUpdate()，其待处理更新会合并；视频帧到达后不等于都进行了原生绘制。实际测试 4K 约 60fps 的帧信号接近 60，但常规窗口只有约 52 次/秒渲染提交。

- 在 Windows + 精确 Qt 6.10.3 版本下，找到本视频控件独有的 QVideoWindow；帧到达后逐帧提交，拦截重复的排队 UpdateRequest。
- 保留 Qt 原生渲染、GPU 解码和垂直同步，不下载每个视频帧为图片，不增加转码或代理视频。窗口 Expose/resize 仍交给 Qt。
- 版本不匹配或找不到唯一窗口时自动退回 Qt 默认方式；CHRONOVIEW_VIDEO_PRESENTATION=qt 及绿色版“兼容播放.cmd”提供显式回退。
- 新增原生帧提交/清空、暂停缩放、释放及回退检查。增加打包 EXE 的显式只读测量入口与验证脚本。

## 边界和交付

新版 dist/ChronoView-0.2.9/ChronoView.exe，未制作安装包，依赖及许可证未改变。没有采用尝试过的 Qt Quick 原型或全局 D3D 环境参数。

本次原生窗口抓取工具因运行时路径错误无法连接，不能声称已通过截图/录屏目视验证。原生提交与解码计数用于复现程序内部漏绘，不保证屏幕物理帧率、所有显卡或主观音画同步；测试为静音。HDR、多显卡/虚拟显示器、多 DPI、长时间压力和超过屏幕刷新率的视频尚未全面验证。仍可能有首帧、短时调度延迟或源文件时间戳不均匀。该桥接依赖所固定的 Qt 实现；升级 Qt 时需重新审阅，否则自动回退。

历史验证见 docs/validation/v0.2.8.md。Qt requestUpdate 更新合并语义参见 https://doc.qt.io/qt-6.10/qwindow.html#requestUpdate 。
