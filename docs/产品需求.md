# Windows 本地照片与视频浏览软件完整开发需求

## 一、项目目标

请从零开始开发一款 Windows 本地照片与视频浏览软件，使用 Python + PySide6 构建图形界面。

本软件主要用于浏览和管理存储在 SATA SSD 移动硬盘中的照片和视频，界面风格参考 iPhone 相册，要求简洁、现代、美观、操作方便。

软件的核心功能是：

1. 自动扫描用户指定文件夹及其所有子文件夹中的照片和视频。
2. 自动解析照片、视频文件名中包含的时间信息。
3. 忽略文件名前面的 `IMG`、`VID` 类型标识，按照时间顺序混合排列照片和视频。
4. 支持按照年份、月份分类浏览。
5. 支持照片缩略图展示、大图查看，以及视频播放。
6. 不修改、不移动、不重命名、不删除移动硬盘中的原始文件。
7. 可以在一台 Windows 电脑上开发，再打包为 EXE 程序或安装包，在其他 Windows 电脑上直接使用。

本项目为完全本地运行的软件，不需要联网、用户登录、云存储或服务器。

## 二、文件夹扫描与照片库管理

### 2.1 支持多层文件夹结构

用户的照片可能按照年份和月份存放，例如：

```text
E:\Photo\
│
├── 2024\
│   ├── 01\
│   │   ├── IMG20240101120000.jpg
│   │   └── VID20240101123000.mp4
│   └── 02\
│       └── IMG20240210152030.jpg
│
├── 2025\
│   ├── 01\
│   │   ├── IMG20250102103000.jpg
│   │   └── VID20250102110000.mp4
│   └── 12\
│       └── IMG20251225183000.jpg
│
└── 2026\
    ├── 01\
    │   ├── IMG20260101103000.jpg
    │   └── VID20260101110000.mp4
    └── 02\
        └── IMG20260215123045.jpg
```

上述仅为示例，实际文件夹名称及层级可能不同。

用户只需要选择最外层的 `E:\Photo` 文件夹，软件就应自动扫描该目录及其所有下级目录，不需要逐个选择年份或月份文件夹。

具体要求：

- 使用递归扫描方式查找照片和视频。
- 不限制正常的文件夹嵌套层级。
- 支持照片和视频分散在任意子文件夹中。
- 支持同一文件夹内同时包含照片、视频和其他类型文件。
- 忽略不支持的文件类型。
- 使用文件完整路径区分不同文件，避免相同文件名造成冲突。
- 避免因为目录链接形成循环扫描。
- 对无权限、不可访问、损坏的目录进行异常处理。
- 扫描过程不能阻塞图形界面。

### 2.2 照片库路径管理

软件首次启动时，允许用户选择照片库根目录。

要求：

- 可以选择电脑内部硬盘或外接移动硬盘中的文件夹。
- 记住上次选择的照片库路径。
- 下次启动时自动恢复照片库。
- 不能把 `E:\Photo` 等示例路径写死在代码中。
- 移动硬盘盘符发生变化时，允许用户重新定位照片库。
- 移动硬盘未连接时，显示友好提示，不得崩溃。
- 移动硬盘重新连接后，可以重新扫描并恢复浏览。
- 文件夹内新增照片和视频后，用户可手动点击“刷新照片库”，重新扫描更新内容。

## 三、文件名时间解析与排序

### 3.1 文件名格式

照片文件名示例：

```text
IMG20260101103000.jpg
IMG20260215123045.png
IMG20260320152030.jpeg
```

视频文件名示例：

```text
VID20260101110000.mp4
VID20260215150030.mov
```

文件名规则：

```text
IMG + YYYYMMDDHHMMSS + 扩展名
VID + YYYYMMDDHHMMSS + 扩展名
```

其中：

- `IMG`：照片。
- `VID`：视频。
- `YYYY`：年份。
- `MM`：月份。
- `DD`：日期。
- `HH`：小时。
- `MM`：分钟。
- `SS`：秒。

例如：

`IMG20260101103000.jpg`

表示 2026 年 1 月 1 日 10:30:00 拍摄的照片。

### 3.2 时间解析规则

软件必须：

1. 自动识别 `IMG`、`VID` 前缀。
2. 提取后面的 14 位时间数字。
3. 将时间转换为实际日期时间。
4. 验证日期是否合法，不能仅检查数字长度。
5. 根据解析得到的日期时间排序。
6. 照片和视频参与同一个排序序列，不按文件类型分开。
7. 对不符合规则或日期无效的文件，统一归入“未识别日期”。
8. 日期相同时，使用文件完整路径作为稳定的次级排序依据。
9. 不依赖 Windows 文件创建时间或修改时间作为主要排序依据。
10. 不允许为了实现排序而修改原文件名。

### 3.3 排序方式

支持：

- 从新到旧：默认。
- 从旧到新：可切换。

示例：

```text
IMG20260101100000.jpg
VID20260101103000.mp4
IMG20260101110000.jpg
VID20260101123000.mp4
```

按照时间从旧到新排序时，应严格按照上述顺序显示。

## 四、按年份与月份浏览

这是本软件的核心功能之一。

### 4.1 全部照片

提供“全部照片”页面：

- 展示所有扫描到的照片和视频。
- 按时间从新到旧排列，允许切换排序方向。
- 照片与视频混合显示。
- 显示照片总数、视频总数。

### 4.2 按年份浏览

软件自动根据文件名中的时间生成已有年份。

例如：

```text
全部照片

2026年
2025年
2024年
```

点击某一年后，展示该年份的照片和视频。

年份列表必须根据实际数据自动生成，不使用固定年份。

### 4.3 按月份浏览

用户选择年份后，可以进一步选择月份。

例如：

```text
2026年

1月    356个文件
2月    218个文件
3月    421个文件
4月    185个文件
...
```

要求：

- 点击月份后展示对应月份中的所有照片和视频。
- 同一月份内按照完整时间排序。
- 每个月显示照片和视频的总数量。
- 没有文件的月份可以不显示或显示为空状态。
- 支持从月份返回年份，再返回全部照片。
- 即使照片放在错误年份或月份的物理文件夹中，也应以文件名解析出的日期为准进行分类。

例如：

```text
E:\Photo\2025\12\IMG20260101103000.jpg
```

虽然实际存放在 2025 年 12 月的文件夹中，但软件应将其显示在 2026 年 1 月。

软件只改变界面中的分类结果，不修改原始文件位置。

### 4.4 未识别日期

增加“未识别日期”分类，用于展示文件名时间无法正确解析的照片和视频。

这些文件仍然允许正常查看和播放，不能直接忽略或删除。

## 五、照片浏览功能

软件使用缩略图网格展示照片。

功能要求：

1. 自动生成图片缩略图。
2. 缩略图保持正确的长宽比例，不得拉伸变形。
3. 支持调节缩略图大小。
4. 窗口尺寸变化时自动调整网格列数。
5. 支持鼠标滚轮浏览照片列表。
6. 双击照片打开大图查看。
7. 支持放大、缩小和鼠标滚轮缩放。
8. 支持适应窗口与原始尺寸显示。
9. 支持全屏查看。
10. 支持键盘左右方向键切换上一项、下一项。
11. 正确处理照片的 EXIF 方向信息。
12. 无法读取的图片显示错误占位图，不影响其他文件浏览。

优先支持以下图片格式：

- JPG
- JPEG
- PNG
- WebP
- BMP
- HEIC / HEIF（在具备相应解码能力时支持）

对于 HEIC 格式，应明确处理所需的解码依赖，并确保打包后仍可以使用。

## 六、视频浏览与播放

视频必须与照片一起展示在同一个时间序列中。

具体要求：

- 支持自动生成视频缩略图。
- 视频缩略图显示明显的播放标识。
- 尽可能显示视频时长。
- 点击视频进入播放界面。
- 支持播放、暂停、音量调节和进度条拖动。
- 支持全屏播放。
- 切换到其他文件时应正确释放播放资源。
- 无法解码的视频显示友好提示，不得导致软件崩溃。

优先支持：

- MP4
- MOV
- AVI
- MKV（尽可能支持）

可以考虑 Qt Multimedia 和 FFmpeg 等技术，但应优先确保最终打包版本具备可靠的兼容性。

## 七、界面设计

### 7.1 总体风格

软件界面参考 iPhone 相册以及现代 Windows 应用。

要求：

- 整体简洁、美观。
- 使用圆角、适当留白和统一图标风格。
- 支持深色和浅色主题。
- 支持窗口最大化和自由调整大小。
- 在常见的 1080P、2K、4K 屏幕上正确缩放。
- 不要使用过于复杂、类似传统文件管理器的界面。

### 7.2 主界面结构

左侧导航栏：

```text
我的照片

全部照片
按年份
按月份
未识别日期

照片库
选择文件夹
刷新照片库
```

顶部工具栏：

```text
当前年份 / 月份
排序方式
缩略图大小
照片数量
视频数量
主题设置
```

主区域：

- 使用照片和视频缩略图网格。
- 根据当前选择的年份、月份动态显示内容。
- 点击缩略图进入查看界面。
- 无照片时显示简洁的空状态页面。

### 7.3 交互要求

- 页面切换流畅。
- 不出现长时间无响应。
- 扫描时展示进度或状态信息。
- 照片数量较多时允许先显示已经加载的内容。
- 缩略图未生成时先显示占位图。
- 后台生成缩略图完成后自动更新界面。

## 八、性能与缓存

本软件可能需要处理数万张照片和大量视频，因此必须考虑性能问题。

具体要求：

1. 使用后台线程扫描照片库。
2. 扫描过程中保持 GUI 可交互。
3. 使用缩略图缓存，避免每次启动都重新生成所有缩略图。
4. 按需加载当前可见区域的缩略图。
5. 不允许一次性将所有原始照片读取到内存。
6. 优先使用 Qt 的 Model/View 架构或其他适合大量数据的方案。
7. 软件滚动大量照片时应尽量保持流畅。
8. 对文件路径、文件大小、修改时间等信息建立本地索引。
9. 对新增、删除或修改过的文件进行增量扫描。
10. 扫描和缓存任务支持取消。
11. 退出程序时正确结束后台任务、释放资源。

缓存与索引推荐使用：

- SQLite：存储照片文件索引与时间信息。
- 用户缓存目录：保存缩略图。
- Windows 用户配置目录：保存程序设置。

数据库和缓存保存在电脑本地，不保存在移动 SSD 中。

原始照片与视频仍然保存在用户指定的文件夹中。

## 九、原始文件安全要求

本软件主要用于浏览，不提供文件修改功能。

必须遵守：

- 不删除照片或视频。
- 不重命名照片或视频。
- 不移动照片或视频。
- 不修改原文件内容或元数据。
- 不在原照片文件夹中自动生成缩略图文件。
- 不自动格式化或调整移动硬盘分区。
- 不因移动硬盘断开而清空照片库数据。
- 扫描异常不能导致原始文件损坏。

软件应尽可能以只读方式打开原始文件。

## 十一、跨电脑安装与使用

软件在当前 Windows 电脑上开发，但必须支持安装到其他 Windows 10/11 64 位电脑。

要求：

1. 不依赖目标电脑预先安装 Python。
2. 不要求目标电脑安装 PySide6。
3. 使用 PyInstaller 打包独立运行版本。
4. 使用 Inno Setup 制作 Windows 安装包。
5. 支持桌面快捷方式和开始菜单快捷方式。
6. 支持正常卸载软件。
7. 软件安装路径允许用户选择。
8. 禁止硬编码开发电脑的绝对路径。
9. 支持中文路径、空格以及 Unicode 文件名。
10. 首次启动时让用户选择照片库。
11. 安装在其他电脑后，重新选择照片库即可浏览对应硬盘中的照片和视频。
12. 正确打包所需的 Qt 插件、图像解码器、视频依赖和资源文件。
13. 针对缺失依赖或不支持的格式，提供明确错误提示。

需要同时提供：

- 免安装绿色版。
- 正式 Windows 安装版。
